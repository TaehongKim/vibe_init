# 작업 워크플로우

## 세션 시작 시

1. `progress.md` 읽기 → 현재 상태 파악
2. `plan.md` 읽기 → 이번 세션 작업 범위 확인
3. 관련 기능이 있으면 `prd.md` 해당 섹션 확인
4. 작업 시작 전 계획을 한 줄로 요약해서 말할 것

## 작업 완료 시

- 완료 항목: `progress.md` 체크박스 업데이트
- 새 이슈: `progress.md` 이슈 테이블에 추가
- 설계 결정: `plan.md` ADR 섹션에 기록

## 여러 파일 동시 수정 시 의존성 순서

```
lib/ → types/ → validations → actions/ → api/ → components/ui/ → components/도메인 → page.tsx
```

## 모르거나 불명확한 것이 있을 때

임의로 결정하지 말고 먼저 질문할 것. 특히:
- 기존 파일 삭제·대규모 리팩토링 시
- `prd.md`에 없는 기능 추가 시
- 스택에 새 라이브러리 추가 시
- DB 스키마 변경 (마이그레이션 필요) 시

## 커뮤니케이션 규칙

**사용자와의 모든 대화·질문·보고·진행 상황은 반드시 한국어로 작성할 것.**

### 작업 시작 보고

```
📋 작업 계획
- 읽은 파일: progress.md, plan.md
- 현재 상태: [한 줄 요약]
- 이번 세션 목표: [구체적인 파일 또는 기능]
- 예상 순서: 1) ... 2) ... 3) ...
```

### 작업 중 보고

```
✅ lib/auth.ts 완성 — LDAP CredentialsProvider 구현
⏳ 다음: app/api/auth/[...nextauth]/route.ts 작성 중
```

### 질문 형식

```
❓ 확인 필요
[질문 내용]
선택지:
  A) ...
  B) ...
확인 후 진행하겠습니다.
```

### 작업 완료 보고

```
✅ 세션 완료 요약
완료한 작업:
- [파일명]: [무엇을 구현했는지]

업데이트한 문서:
- progress.md: [어떤 항목 체크]

다음 세션에서 이어할 작업:
- [파일명 또는 기능]
```

### 에러·이슈 발생 시

```
🔴 이슈 발생
증상: [어떤 에러]
원인 추정: [왜 그런 것 같은지]
시도한 것: [무엇을 해봤는지]
제안: [해결 방법]
```
