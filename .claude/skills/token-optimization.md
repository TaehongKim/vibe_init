# 토큰 최적화

## 왜 중요한가

토큰 낭비는 누적된다. 세션 시작 시 불필요하게 파일 5개를 읽으면, 프로젝트 수명 내내 매 세션마다 그 토큰을 소모한다. 100회 세션 기준으로 일일 한도에 큰 부담이 되고 유료 플랜에서는 실질적인 비용이 된다.

세 역할 팀은 이 낭비를 구조적으로 차단한다 — 규칙이 CLAUDE.md에 내장되어 자동으로 적용되며, 매번 상기시킬 필요가 없다.

## 다섯 가지 규칙

모든 세 역할 팀 세션 라우터에 내장된 규칙:

```
스킬 또는 메모리에 있는 내용인가?   → 신뢰하고 파일 읽기 생략
추측성 도구 호출인가?               → 취소
병렬 실행 가능한 호출인가?          → 병렬화
20줄 초과 출력이지만 필요 없는가?   → 서브에이전트로 라우팅
사용자 말을 다시 반복하려는가?      → 삭제
```

## RTK — Bash 출력 압축

토큰 최적화는 팀이 어떻게 생각하고, 읽고, 응답하는지를 제어한다. RTK는 bash 명령에서 돌아오는 출력을 처리한다.

[RTK](https://github.com/rtk-ai/rtk)는 bash 명령 출력이 Claude의 컨텍스트 창에 들어오기 전에 압축하는 별도 도구다. `find`, `ls`, `grep` 같은 명령은 수백 줄을 반환할 수 있는데, RTK가 그 출력을 가로채 압축하여 bash 출력 토큰을 자동으로 50~70% 줄인다.

RTK는 세 역할 팀의 일부가 아니며 별도로 관리되지 않는다. Claude Code CLI를 집중적으로 사용한다면 별도로 설치할 것. RTK(bash 레이어) + 토큰 최적화(행동 레이어)의 조합에서 실제 절감 효과가 배가된다.

설치: https://github.com/rtk-ai/rtk

## Grep 후 Read

파일 전체를 읽어서 하나를 찾지 말 것. 먼저 정확한 문자열이나 줄 번호를 grep으로 찾고, 주변 컨텍스트가 필요하면 Read에 offset과 limit을 사용할 것. 이 단일 규칙이 활성 빌드 세션에서 가장 큰 효과를 낸다.

## 역할별 로딩 범위

각 역할은 자신의 업무에 필요한 것만 로드한다:
- 기획자: checkpoint + BUILD-LOG + ARCHITECT-BRIEF
- 개발자: ARCHITECT-BRIEF + 관련 참조 파일만
- 검토자: REVIEW-REQUEST + 개발자가 명시한 특정 파일들

전체 프로젝트 스펙, 스키마, 흐름 문서는 명시적으로 필요할 때까지 디스크에 유지한다.

## 체크포인트 우선

SESSION-CHECKPOINT.md가 최신 상태일 때는 BUILD-LOG와 전체 스펙을 읽는 것을 대체한다. 기획자가 매 세션 종료 시 작성한다. 내용: 어디서 멈췄는지, 무엇이 결정됐는지, 무엇이 미결인지, 정확한 재개 프롬프트.

## CLAUDE.md는 라우터

CLAUDE.md는 약 50줄을 초과해서는 안 된다. 지식 베이스가 아닌 라우팅 파일이다. CLAUDE.md의 모든 바이트는 매 세션마다 토큰 비용이 발생한다. 간결하게 유지할 것.
